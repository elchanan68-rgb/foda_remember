# סבתא פודה — משפחת סמינה

אלבום זיכרונות משפחתי בעברית. לאחר חיבור Supabase, סיפורים ותמונות משותפים לכל בני המשפחה. כברירת מחדל סיפורים חדשים ממתינים לאישור; אפשר להגדיר קוד משפחתי סודי לפרסום מיידי.

## מה כבר מוכן

- מסד נתונים לסיפורים וסטטוס אישור (`pending`, `approved`, `rejected`).
- Edge Function שמקבלת סיפורים ותמונות, בודקת את הקלט, מאמתת Cloudflare Turnstile, ומגבילה שליחות לפי כתובת IP מגובבת.
- תמונות נשמרות ב־Storage פרטי. האתר מקבל קישורי צפייה זמניים רק לתמונות של סיפורים מאושרים.
- מקטע קורות חיים ציבורי עם תקציר, מקום לידה, ילדות, הורים, עלייה לארץ וסיפור מלא. כל מבקר באתר יכול לערוך אותו; השינויים נשמרים ב־Supabase.
- הטופס מזהה JPG, PNG ו־WebP לפי תוכן הקובץ ולא לפי שם או רישיות הסיומת, מציג תצוגה מקדימה, מידות וגודל משוער אחרי כיווץ, ומגביל העלאה ל־8MB.
- אין מפתח Supabase סודי, `service_role` או Turnstile secret בקוד הדפדפן.
- כל עוד לא הוגדר endpoint, האתר ממשיך לשמור זיכרונות מקומית בדפדפן הנוכחי בלבד.

## חיבור הפרויקט ל־Supabase

1. יוצרים פרויקט Supabase וחשבון Cloudflare Turnstile, ומגדירים ב־Turnstile את הדומיין שבו האתר יתארח.
2. מתקינים את Supabase CLI, נכנסים לחשבון ומקשרים את התיקייה לפרויקט:

   ```sh
   npx supabase login
   npx supabase link --project-ref YOUR_PROJECT_REF
   npx supabase db push
   npx supabase functions deploy family-memories
   ```

   קובץ `supabase/config.toml` מגדיר את פונקציית השליחה כ־public כדי שנכדים יוכלו לשלוח בלי חשבון. ה־POST דורש Turnstile, אימות שרת והגבלת קצב. כברירת מחדל התוכן ממתין לאישור ידני.

3. ב־Supabase Dashboard פותחים **Edge Functions → Secrets** ומגדירים:

   - `TURNSTILE_SECRET_KEY` — המפתח הסודי של Turnstile.
   - `ALLOWED_ORIGINS` — כתובות origin מלאות ומדויקות, מופרדות בפסיקים. לא כוללים נתיב. עבור האתר הנוכחי יש להגדיר `https://elchanan68-rgb.github.io` (בלי `/foda_remember/`).
   - `FAMILY_AUTO_APPROVE_CODE` — קוד אקראי ארוך שתבחרו ותשתפו רק עם בני משפחה מורשים. שליחה עם הקוד תאושר אוטומטית; שליחה בלעדיו תמתין לאישור. אל תשתמשו בביטוי צפוי כמו "סבתא פודה", ואל תכניסו את הקוד ל־GitHub או ל־`public-config.js`.

   Supabase מספקת לפונקציה את `SUPABASE_URL` ואת מפתח השרת שלה בסביבת הריצה. אין להעתיק את מפתח השרת לקובץ אתר, ל־`public-config.js`, או למאגר Git.

4. מעדכנים ב־`public-config.js` את `apiUrl` לכתובת הפונקציה: `https://vounucrbdghsuczttvlj.supabase.co/functions/v1/family-memories`, ואת `turnstileSiteKey` למפתח האתר הציבורי של Turnstile. כתובת האתר היא `https://elchanan68-rgb.github.io/foda_remember/`. כתובת הפונקציה ומפתח האתר הציבורי גלויים בדפדפן בכוונה; הם אינם מפתחות סודיים. יש להגדירם רק אחרי פריסת הפונקציה והסודות, כדי שהאתר לא ינסה להתחבר לפני שהשירות מוכן.

5. מפרסמים מחדש את קובצי האתר. ב־Supabase Dashboard פותחים את הטבלה `family_memories`, בודקים סיפורים חדשים שמצבם `pending`, ומשנים למצב `approved` כדי לפרסם אותם. בחירה ב־`rejected` משאירה אותם מוסתרים. מי שמקבל את קוד הפרסום האוטומטי יכול לפרסם תוכן ישירות, לכן יש לשתף אותו רק עם אנשים שסומכים עליהם.

   אחרי הוספת המיגרציה `202610190003_family_biography.sql` והפריסה, פותחים באתר **קורות חייה → עריכת קורות החיים** וממלאים את השדות. לא נדרש קוד; כל מי שנכנס לאתר יכול לשנות את התוכן. התקציר והסיפור המלא הם שדות חובה; הפרטים האחרים יוצגו רק אם מולאו.

## הרצת פונקציה מקומית

מעתיקים את `supabase/functions/.env.example` אל `supabase/functions/.env`, ממלאים ערכים מקומיים בלבד ומריצים את Supabase המקומי. קובץ `.env` מוחרג מ־Git. ב־`ALLOWED_ORIGINS` מוסיפים את כתובת שרת הפיתוח המקומי. אין לשמור מפתחות אמיתיים ב־`.env.example` או בקובצי האתר.

## הגבלות ופרטיות

- מתקבלים סיפורים באורך של עד 2,500 תווים ותמונות JPG, PNG או WebP עד 8MB.
- מכסת אחסון התמונות באתר נעצרת ב־800MB (80% ממכסת 1GB של Supabase Free). בדיקת המכסה מתבצעת בשרת, סופרת את כל הקבצים בכל ה־buckets בפרויקט הזה, ומשריינת מקום בזמן העלאה כדי למנוע משתי העלאות מקבילות לעבור את הסף. עם ההגעה לסף מופיעה התראה באתר, והעלאת תמונות נעצרת; אפשר להמשיך לשלוח סיפורים ללא תמונה. ההתראה מוצגת למי שנמצא באתר, לא נשלחת כהודעת דוא״ל.
- Supabase מודדת שימוש אחסון לפי GB-hours כממוצע לאורך תקופת החיוב. מגבלת 800MB כאן היא תקרה מקומית שמרנית לפי הנפח הנוכחי בפרויקט; היא לא קוראת שימוש מפרויקטים אחרים באותו ארגון. יש לבדוק גם את עמוד Usage בחשבון Supabase.
- קורות החיים נשמרים בטבלה פרטית ונקראים דרך הפונקציה. עדכון באתר פתוח לכל מבקר ומוגבל לחמישה ניסיונות בשעה לכל כתובת IP. הגבלת קצב אינה אימות זהות, ולכן כל מבקר יכול לשנות את קורות החיים.
- כל תמונה נבדקת לפי תוכן הקובץ ולא רק לפי הסיומת או הכותרת שהדפדפן שולח.
- הסיפורים ציבוריים רק אחרי אישור. תמונות נשארות ב־bucket פרטי ומוצגות באמצעות קישור חתום שפג אחרי 30 דקות.
- מונה ההגבלה שומר גיבוב SHA-256 של כתובת IP, לא את הכתובת עצמה, ומנקה רשומות ישנות.
- שמירת כתובת IP תלויה בכותרות שה־proxy של Supabase מעביר. Turnstile ואישור ידני נשארים שכבות ההגנה גם אם כותרת ה־IP אינה זמינה.
- בלי פרטי פרויקט ופריסה בפועל, האתר נשאר במצב מקומי ואינו משתף תוכן בין מכשירים.
